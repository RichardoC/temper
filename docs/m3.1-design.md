# M3.1 design — property-reward selection: the toot thesis, measured

Status: **rev1** (authored 2026-10-24 after M3.0-P3 completed; basis is the
P3 report `docs/m3.0-p3-report.md` at `b16b75d` and the instruments doc).
GPU for the cells is operator-pre-approved (2026-10-24 session).

Pre-registration discipline continues from M3: every cell, gate, ranking rule
and replication standard below is frozen BEFORE any cell generates; changes
after a cell starts are labeled amendments in a changelog, never silent.

## §0 The question M3.1 answers

M3.0-P3 closed the book on its own framing. The mechanism question it asked —
*does verifier-controlled compute reallocation beat diverse-sampling-plus-filter
at matched NFE?* — was answered **no, not detectably**: at the frozen demoted
scope the in-loop engine row is late-window-advisory-only, and the measured
C-full − C-null +3 decomposes into (i) better draws (4/4 counterfactual
divergences are different canvases, not different rankings) and (ii) better
picks. The one flip with a reachability narrative (HumanEval_25) did not
replicate at 2 games. What survived the attribution gate is this:

> **Selection is the live lever.** C-null's 8-canvas ensembles *contain* a
> container-OK canvas for 16/25 problems (the oracle), but every emission rule
> in M3.0 recovered only 14/25. Mean-commit-confidence ranks a
> compile-clean-but-wrong canvas above a compile-clean-and-correct one
> (measured: C-screen forfeited HumanEval_1 and _9; structural forfeited _24
> and _25). The screen sees the solution and hands it back.

M3.1 asks the question the project was built for:

> **Can execution-grade property evidence — proptest harnesses generated at
> inference time from the problem contract, executed by cargo against
> candidate canvases — rank candidates better than compile-clean +
> commit-confidence, and convert the measured 16-vs-14 selection headroom into
> container-confirmed passes at matched generation NFE?**

This is the original toot thesis: joint search over code space (the diffusion
LM's canvases) and input space (proptest's generated inputs), with the Rust
toolchain as the inference-time discriminator. In M3.1 the join happens at
SELECTION, not mid-decode: D4 measured that mid-canvas recall of informed
evidence is ~0, and P3 confirmed reordering mid-decode buys nothing at this
scale; the honest place the property signal can act is the final window.

Scope guardrails carried over verbatim:
* **Properties steer, never score.** No property or harness result may enter
  an official benchmark verdict. Container scoring (humaneval-rs official
  tests) remains the only pass/fail instrument, exactly as in M3.0.
* No reference leakage: harness generation sees the problem **prompt
  (docstring + signature) only** — the same context the canvas generator sees.
  The official test string is never shown to any generator.
* C-kill/c-clone stay dropped (M3.0 cut order; the R0 false-kill fix is
  necessary but not sufficient to re-enable them, and M3.1 does not need them).
* GPU/OPS guardrails unchanged (Rancher closed during generation; scoring
  windows only after ps-verified model exit; ≤1800 s polls; no turn finalized
  mid-cell).

## §0.5 What must be true (falsifiable form)

The design lives or dies on a simple correlation claim:

> On canvases that are R1-clean (compile-clean), property pass/fail separates
> container-OK from container-rejected **better than mean-commit-confidence
> does**, on the exact problems P3 measured the screen mis-ranking
> (HumanEval_1, 9 for the screen rule; 24, 25 for structural).

If proptest evidence does not re-rank those specific canvases, M3.1 is a null
and M3.1 falls back to reporting the negative with the oracle audit. That
failure mode is cheap to reach (the primary cell is offline).

## §2 Machinery (everything reused, one new rung)

1. **Property harness generation** — the diffusion LM (same substrate,
   uniform across the program) drafts **H = 2** property files per problem at
   T = 0.2, steps = 256, seeds 0/1: a proptest `properties.rs` exercising the
   problem's contract (examples from the docstring, metamorphic relations,
   boundary inputs). Input: prompt-only (`<problem>__prompt.txt`, no tests,
   no solution). Output pinned by `strategy_hash_of(properties.rs)`.
2. **Freeze validation** (CPU, before any cell): each harness must
   **compile** against a signature stub (`todo!()` body) emitted into the
   template — proving the harness matches the prompted signature and does not
   import the benchmark's tests. Runtime behavior at freeze is expected
   `abort` on the stub; only compile success is required. Harnesses that fail
   validation are replaced by a seed-2 draft (pre-registered replacement rule,
   logged); the *final frozen set* (sha list) is committed before cells.
3. **New rung R3** in the verdict ladder, config **v3**: run the frozen
   harness set against a **completed, zero-hole, R1-clean** canvas with
   `run_candidate` (seatbelt sandbox, 256 proptest cases). R3 fires
   **final-window only** — never mid-canvas (D4's negative stands).
   Ranking rule (`emission` v3, pre-registered):
   **`pass_rate over non-timeout harnesses`, then mean_commit_conf, then
   lowest temp, then lowest index** (confirming the screen's existing tie
   order). `timeout` counts as abstention, never as failure (a candidate the
   harness cannot judge is unknown, not wrong — and aborting ≠ failing is the
   difference between evidence and punishment).
4. **Cells** consume R3 two ways:
   * offline reranking of a banked ensemble (pure rule delta), and
   * in-loop final-window selection inside `run_game` (emission-only changes;
     no budget moves, no kills).

D-instruments extended, all before the GPU cells: D1 times the full R3
protocol at freeze validation; D2 logs every R3 call (problem, harness sha,
canvas, status, duration, `minimal_input`); D3 meters R3 calls/wall into the
10 % criterion; D5 allowlist gains R3; D6 gains the M3.1 comparisons; D7
freezes config v3 **and the frozen harness sha list** (tamper-checked like
the v2 sha).

## §3 The cell grid

All generation cells keep the rev2 ladder and envelope semantics (8 slots ×
256 steps = 2048 NFE/problem; problems by NUMBER 0…21, 23, 24, 25; seeds
FLAT; structural T = 0.2 emission-preferred anchor row preserved).

| cell | GPU? | content | cost |
|---|---|---|---|
| **P-gen** | yes | 25 problems × 2 property harnesses, T=0.2 draft, 256 steps | 12 800 NFE ≈ **3.6 h** |
| **P-prop-screen** | **no** | rerank the BANKED C-null ensemble (M3.0 Phase A sidecars, sha-pinned) with R3 ranking; emit per v3 rule; container-score the emissions in one window | ~1 h CPU+cargo |
| **P-prop-engine** | yes | `run_game` 25 problems, engine fires R3 at final window for emission ranking (config v3; kill/clone off; no mid-decode action) | 51 200 NFE ≈ **15 h** |
| **P-25re** | yes | HumanEval_25 re-decide: 4 base seeds (2000…2003) × **both roles** (unsteered ladder game + engine game), paired-on-seed | 16 384 NFE ≈ **4.7 h** |
| oracle audits | no | oracle-of-C-full; property/correlation tables on every ensemble | minutes |

Pre-flight gate before P-prop-engine (pattern from P3): 2 problems × 8 × 32
steps through the R3-wired loop, gates on R3 call count == expected, R3 wall
share ≤ 10 %, emission identical-or-better vs confidence rule on the
smoke set, suite green.

**Comparisons** (D6, sign-test primary everywhere; Jeffreys reporting-only):

* **PRIMARY: P-prop-screen vs C-screen, same-ensemble rule delta.** This is
  the cleanest mechanism comparison in the program's history: identical 200
  canvases, identical everything except the ranking rule — no draw variance,
  no temperature cliff, no luck. Every flip is *by construction* a selection
  effect.
* Secondary: P-prop-screen vs C-null (property rule vs structural on the same
  ensemble — the other half of the forfeited set {24, 25}).
* Secondary: P-prop-engine vs a **P-prop-screen twin over the engine's own
  ensemble** (same-draws rule delta, the P3 canvas-pair-diff discipline), and
  totals vs C-full's 17.
* P-25re classification (§4 G5).

## §4 Gates (pre-registered, one primary each)

* **G1 RECOVER (primary)**: P-prop-screen ≥ **16/25** on the C-null ensemble —
  the property rule must recover the measured headroom on its own turf.
  Primary sign test: P-prop-screen vs C-screen over the same ensemble;
  expected discordant set is small, so ALSO margin-based: net flips-up ≥ +2.
  Honest power: at n=25 with ~2–4 discordant pairs, conventional α=0.05 is
  unreachable; the pre-registered decision quantity is the +2 margin with
  attribution (below), consistent with how M3.0 was adjudicated.
* **G2 ATTRIBUTED-SELECTION**: every flip counts only if (a) both rules ranked
  the same 8 canvases, (b) the confidence rule emitted a container-rejected
  canvas, (c) an OK canvas existed in that ensemble (oracle member, measured
  offline), (d) the property rule emitted one of the OK canvases. Flips are
  **selection-attributed by construction**; any flip failing (c) is reported
  but not claimed.
* **G3 ENGINE**: P-prop-engine ≥ 17/25 **and** no regression vs 17 with wins
  coming from the engine's own oracle audit (measured before the cell runs).
* **G4 PROPERTY-QUALITY**: on the frozen set: harness compile rate at freeze
  ≥ 90 %; and on canvases where properties and confidence disagree
  (R1-clean, one says OK-candidate by container verdict), properties are
  right more often — the §0.5 correlation, reported as a table either way.
* **G5 H-25 CLASSIFICATION** (4-game standard, pre-registered): engine passes
  ≥ 3/4 **and** unsteered passes ≤ 1/4 ⇒ engine-specific reachability claim
  admissible (reported with exact counts, not a p-value ritual). Otherwise:
  the P3 flip is classified **draw-luck** and the attribution note in
  `m3.0-p3-report.md` is amended to CLOSed-luck, with no mechanism claim.
* **SHIP** = G1 + G2 (selection mechanism established on held-fixed draws).
  **STRONG** = SHIP + G3 (engine ≥ 18/25 strictly better than the program
  best) + G5 in the engine's favor. Anything else is reported as the honest
  intermediate.

## §6 Predictions on record (falsifiable, before any cell)

1. Pessimist (review-B style): P-prop-screen nets **+0 or +1** — weak
   properties pass wrong-but-plausible code as often as confidence misses it,
   so the primary returns a draw. Consequence accepted: report null.
2. Parent prediction: **+2 with both {1, 9} recovered** (the screen's own
   measured misses, where an OK canvas is provably in-pool), giving 16/25 on
   G1 exactly at the oracle line; P-prop-engine ≥ 17 with its wins
   concentrated in its own audit-identified forfeits.
3. Optimist: property evidence also flips 24 or 25 against structural
   (secondary), and the engine reaches **18** — i.e., properties + draws beat
   the program best by a point. Requires G3's engine forfeit audit to show ≥ 1.
4. G5 pessimist: the 4-game re-decide ends draw-luck (P3's failed replication
   was the beginning of that story).

Failure modes priced in: harness compile failures eaten by the freeze-time
replacement rule; timeout-abstain never punished; property/correlation table
(G4) being the honest mirror — if properties rank WORSE than confidence, G1
fails and the negative lands with full tables.

## §7 CLARIFICATIONS (dated; operator ruling 2026-10-24, cited per row)

A **clarification** fills a case the rev1 text left UNDEFINED. It does not
change a pre-registered value, and it is not an amendment — the distinction is
the M3.0 rev2 convention's, kept so a reader can tell a value that was
pre-registered from one that was filled in after the text was frozen. Each row
below was raised by the builder BEFORE the affected code was written and ruled
on by the operator; none was decided by the builder.

| # | revision | what the rev1 text left undefined | the clarification |
|---|---|---|---|
| **C1** | 2026-10-24 | §2.3 defines `pass_rate` over non-timeout harnesses, so a canvas whose harnesses ALL abstain has no defined `pass_rate` and no defined rank. | **Three tiers.** tier 0 = measured `pass_rate > 0` (ordered pass_rate desc, then conf, temp, index) > tier 1 = nothing measured (conf, temp, index) > tier 2 = measured `pass_rate == 0` (conf, temp, index). Abstention can neither beat measured-good (absence of evidence is not better than evidence) nor rank below measured-bad (that would punish abstention, which §2.3 forbids). In an ensemble with no evidence every candidate is tier 1, so the rule reduces EXACTLY to the screen rule — the property the primary comparison needs. All-abstain candidacy is logged as its own D2 event kind and tracked in G4 against container verdicts, so a future rev can re-tier it on measured backing; §2.3's semantics stand until then. |
| **C2** | 2026-10-24 | §2.2 pre-registers ONE replacement round (seed-2 draft) but says nothing about a seed-2 draft that ALSO fails, nor about how G4's compile rate is computed. | A surviving harness on the same problem stands with denominator 1 (logged, shown in G4). **Zero survivors on a problem = STOP and escalate** with the failed drafts attached; the problem is never silently degraded to confidence ranking. G4's >= 90 % compile-rate gate applies to the **50 first drafts** (5 failures is the ceiling); replacement and frozen-set rates are separate reported columns and cannot rescue the gate. |
| **C3** | 2026-10-24 | Phase 2 asks for "the oracle-of-C-full audit from the banked C-full sidecars" and G3 asks that the engine's wins come from "the engine's own oracle audit (measured before the cell runs)" — but the banked C-full cell saved only the EMITTED canvas (25 texts), so no exact C-full oracle is computable at any acceptable cost. | (1) The M3.1 engine seam banks every particle's final canvas (`<out>.canvases/`, text only, I/O never NFE), so P-prop-engine's own oracle is exact and post-hoc, and the same-draws twin over its ensemble is computable. (2) The C-full audit is reported as the **R1-clean-ALTERNATE UPPER BOUND** from steer logs: a ceiling on forfeits, never an "oracle". (3) G3 is read as: pre-cell inputs = P-prop-screen's measured forfeit set + C-full's labeled bound; P-prop-engine's oracle is a POST-HOC attribution column.
