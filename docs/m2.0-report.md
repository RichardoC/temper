## Verdict (3 lines)

1. **The evaluation instrument works end to end**: temper can now export run
   records to official MultiPL-E completion files (stop-marker/fence residue
   stripped, honest exclusion manifest), score them through the pulled
   `ghcr.io/nuprl/multipl-e-evaluation` container via `docker cp` (amd64 under
   Rosetta), and report **both** edition columns (official rustc-2015 vs
   normalized `--edition=2021`) with unbiased pass@k. On the smoke run the
   container's verdicts agreed with temper's own harness on all 4 completions
   (3 OK + 1 SyntaxError), and the unsteered-guise row scored **identically**
   — the format is model-blind, as the decision doc demanded.
2. **The salvage layer converts the M1.5 poster-child failure**: run-B p0's
   stray `pub RingBuf { fn new(..) }` block is repaired deterministically
   (convert pseudo-impl → `impl RingBuf {`) and now reaches **compile ok AND
   proptest pass** — M1.5's "one stray block from passing" candidate is saved
   with zero model calls; the repair fires in `l0` (harness re-verify) and at
   export (record-verdict-driven). Run-B taxonomy histogram matches the M1.5
   hand-count exactly: compile_error=1, renamed_or_self=1, truncated_canvas=2.
3. **NFE accounting is on every new record** (schema v1.2, backward
   compatible): per-candidate `nfe` (forward passes actually executed =
   denoise steps run), run-level `nfe_total` + `verifier_wall_s_total`; plus
   `diag_msg` (primary rustc error string, 500-char cap) so E-code-less
   failures like p0's `missing \`enum\` for enum definition` are visible in
   the record itself.

## Deviations

1. **Smoke test used a fresh sort run instead of the pre-existing records.**
   The task said "no new generation needed", but the pre-existing M1-era sort
   records predate raw sidecars AND store no extracted code — exporting them
   yields 0 completions (verified: all 10 rows across the 4 old records
   excluded with reason "raw text unavailable (pre-M1.5 record)"). A scored
   round trip needs ≥1 completion. The design sanctions generation for
   verification; the fresh K=4 steps=96 run doubles as the NFE/schema-v1.2
   evidence. GPU cost ≈ 12 min.
2. **Repair strategy (a) needed a convert sub-strategy beyond the spec's
   literal "drop unreferenced" wording.** Run-B p0's stray block identifier
   (`RingBuf`) IS referenced by the rest of the code (`RingBuf::new`,
   return types) — dropping it leaves a dangling call and can never reach
   compile-ok, yet the design names exactly this block as example (a) and the
   acceptance demands compile-ok. Implemented as the design intended: drop
   when truly unreferenced, convert the pseudo-impl header when the type
   exists and the body is fn-only. Both sub-strategies are brace-scan based,
   conservative, and separately recorded. No other interpretation of (a)
   reaches the stated acceptance.
3. **Dataset revision differs from the decision doc's pin.** Decision doc:
   `3a9e8d22…`; fetched now: `28441b6024e71d4a1c1c0f6bf171c935cd5a43f2`
   (dataset lastModified 2025-07-15). Counts unchanged (156/354, matching the
   doc's measurements). Recorded in `data/README.md`; no re-pin made.
4. **`--version both` default added** (spec lists `official|normalized`):
   the decision doc requires both columns on every benchmark run; `both` is
   the superset and was used for the smoke.
5. **Run meta also carries `must_define`** (schema v1.2 addition beyond the
   NFE fields): export would otherwise re-derive it from task.toml; carrying
   it in the record keeps records self-describing. Nullable/backward
   compatible like the other v1.2 fields.
6. **Taxonomy maps harness `timeout` to `test_fail`** (no timeout class in
   the spec's 7); gen-errors classify as `None` (infrastructure, not a
   model-output failure) and are excluded from histograms.
7. **ringbuf not container-scored**: `bench/ringbuf` has no
   `multipl_e.tests.rs`, and the export REFUSES to invent scoring tests (by
   design). The p0 repair acceptance is demonstrated against temper's own
   harness (compile ok + proptest pass). Authoring a ringbuf port of the
   approved property for container scoring is available on request — not
   needed for any acceptance item, and each extra hand-authored grader is
   new surface to get wrong.

## M2.2+ notes

1. **Join path is scaffolded, needs generation calibration.** Benchmark-join
   export works (prompt/tests/stop_tokens from the vendored data; body-
   fragment conversion for the single-fn case, with conservative exclusion
   otherwise). Real MultiPL-E benchmark generations need an extract mode that
   produces body fragments natively (MultiPL-E prompts end mid-function; the
   current pipeline extracts whole modules) — the conversion in
   `export.to_body_fragment` covers the common shape; helpers-after-body nest
   legally inside the prompted fn (Rust nested items), but this needs one
   real generation run to validate before the baseline matrix (B1–B3).
2. **pass@10/100 columns need volume**: unbiased pass@10/100 are computed
   only where n≥k; K=4 smoke runs cannot populate them. Baseline-matrix runs
   (20–100 samples/problem per the measurement protocol) will.
3. **Edition delta was zero on the smoke set** — expected for plain-2015-
   compatible code; the delta finding needs candidates with 2018+ idioms
   (`dyn Trait`, async) — i.e. real Dream-Coder Rust generations at scale.
4. **Repair pass coverage is deliberately narrow** (degenerate blocks +
   trailing prose). The other run-B classes (renamed_or_self, truncated
   canvas) are NOT repairable without re-prompting or larger canvas — the
   cheaper fixes remain prompt/anti-prose work and canvas budget (M1.5 note
   stands, now with machine-readable histograms to measure them).
5. **`diag_msg` enables message-pattern compile-error classes** (e.g.
   E-code-less `missing \`enum\``) as a future taxonomy refinement without
   any new plumbing.
6. **Container image is amd64-only, rustc 1.75.0 (2024-07-12)**, per the
   decision doc; an aarch64 image pinned to the M0 toolchain remains the
   parity option if Rosetta slowness matters at baseline-matrix scale.
