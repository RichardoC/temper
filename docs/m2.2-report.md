# temper — M2.2 report (salvaged by parent after worker 8h timeout)

Milestone: **M2.2** — MultiPL-E-Rust baseline pilot, baseline-matrix row **B2**
("Dream-Coder-7B unsteered best-of-K"). Worker committed Phase 1 (driver,
`0e02e23`); generation + scoring completed; report/diagnostics were in flight
when the 8h budget cut the worker. This report was assembled by the parent from
the on-disk artifacts (run records, exports, results, raw sidecars); no work was
re-run.

## Verdict (3 lines)

1. **The instrument works end-to-end at scale**: 25 humaneval-rs problems × K=4
   → 100 samples (NFE 9,600, gen_wall 6.2h) → export both variants → official
   container → dual-edition unbiased pass@k with honest exclusion accounting.
   Pipeline did not drop or corrupt a single row.
2. **The headline number is low but is NOT (yet) a Rust-capability verdict**:
   honest pass@1 = pass@4 = **0.04** (official subset 0.05; normalized edition
   identical) — but 76/80 scored completions fail as `SyntaxError`, and raw-text
   forensics show **adjacent-token corruption** (e.g. `numbers[i + 1]` rendered
   as `numbers + 1]` — a dropped mid-expression span), the classic
   masked-diffusion local-incoherence failure from committing too many tokens
   per denoise step. steps=96 is 25% below our bench-proven 128.
3. **A second, separate disease**: 20/100 rows excluded pre-scoring, clustered
   in exactly 5 problems (HumanEval_4, 15, 17, 18, 19 — all 4 samples each).
   Exclusion classes: `no fenced rust block` ×12, `span does not look like
   Rust` ×4, `required symbol not defined` ×4. Prompt-shape-specific; the model
   answers some HumanEval phrasings with prose.

## Incidents

- Host memory pressure at the end of the run window (macOS killed apps
  system-wide). Contributing load at the timeout: 15GB model process + two
  amd64 scoring containers (Rosetta) + Docker VM, with `PYTORCH_MPS_HIGH_
  WATERMARK_RATIO=0.0` (no MPS self-cap, per spike). Guardrail adopted: never
  overlap generation and container scoring on this host; scoring phases only
  start after the model process has exited (verified via `ps`), and watchers
  confirm free memory before container start.
