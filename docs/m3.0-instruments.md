# M3.0 P0 — instrument deliverables (D1–D7), measured

Milestone: **M3.0 P0** (design `docs/m3-design.md` rev1 `739290b`, §5 phase P0
+ §7 D-deliverables). CPU-only; no GPU, no container. Every number here is
reproducible from committed artifacts with the commands at the bottom.

Scope note: this document covers P0 (D1–D3, D5–D7) and the D4 *scaffold*; D4's
measurement is a P0→P2 boundary activity on real canvases (design §7 D4) and is
reported in the P2 section of `docs/m3.0-report.md`.

## D1 — verifier-rung latency (all 400 rows of the four corrected cells)

`scripts/m3_verifier_latency.py` over the raw sidecars of the four corrected-
basis dLLM cells (s96/s128/s256/s512, 100 rows each).

| rung | what is timed | p50 | p95 | max |
|---|---|---|---|---|
| **R0** shape | `r0_shape` over the rendered canvas (pure python) | **0.088 ms** | 0.118 ms | 0.336 ms |
| **R1** ghost type-check, final checkpoint (zero holes) | `rustc --edition=2021 --crate-type lib --emit=metadata` on the ghost-closed render | **35.8 ms** | 41.5 ms | 44.5 ms |
| **R1** ghost type-check, mid-canvas (30% hole pool, 50% committed) | same, holed program | 33.2 ms | 41.4 ms | 44.4 ms |
| **R2** anti-stub | committed marker scan | free (<1 µs) | — | — |
| **tokenizer decode** per checkpoint render (prompt+384) | `tokenizer.decode` | **2.21 ms** | 2.36 ms | 2.50 ms |
| **R3** M0 harness cycle on a completed fragment | `run_candidate` (cargo check+build+run, 256 proptest cases) | **1667 ms** | 1773 ms | 1773 ms |

Per-cell R1-final p50: s96 34.8 / s128 36.5 / s256 35.8 / s512 36.2 ms — the
design's §3.2 estimate of ~35 ms is confirmed at scale, and the constancy across
cells shows the cost is spawn-dominated, not error-class-dominated (holed
programs cost the same).

**Amortization (D1 acceptance: R1 ≤ 1% of canvas wall).** Worst-case cadence
K_max_eff 8 x 4 checkpoints at R1 p50, against the canvas wall at 1.035 s/NFE:

| envelope | R1 total | canvas wall | fraction |
|---|---|---|---|
| 1024 NFE | 1.168 s | 1059.8 s | **0.110 %** |
| 2048 NFE | 1.168 s | 2119.7 s | **0.055 %** |

Both are two orders of magnitude under the §5 kill-criterion-4 cap (10%), and
under the D1 acceptance bound (1%). **R3 is the real cost** (1.67 s/call here;
the design's 236 ms figure was a warm cache with a trivial property — this is
the honest cold-ish measurement on this host). At the final checkpoint only,
worst case 8 x 1.67 s ≈ 13.4 s ≈ 1.3% of a 1024-NFE canvas wall — still under
the cap, which is why R3 stays final-only and metered.

**R1 instrument validity at the final checkpoint** (post-hoc cross-check
against the container's statuses; the container is never a steer-time signal):

| cell | container class | n rows | R1 any-error flagged | R1 informed-class flagged |
|---|---|---|---|---|
| s256 | SyntaxError | 36 | **36** | 20 |
| s256 | Exception (compiles, panics) | 12 | **0** | 0 |
| s256 | OK | 44 | **0** | 0 |
| s256 | excluded (extract failure) | 8 | 8 | 4 |
| s512 | SyntaxError | 16 | **16** | 16 |
| s512 | OK | 64 | **0** | 0 |
| s128 | SyntaxError | 72 | **72** | 32 |
| s96 | SyntaxError | 60 | **60** | 20 |

This reproduces the design's §3.2 claim exactly: **at zero holes the any-error
screen is exact on compile-deadness — every SyntaxError row flagged, zero OK
rows flagged, and Exception rows correctly cleared** (they compile and panic;
they are R3/held-out territory, not R1's). The informed-class column is the
*mid-canvas* rule and is deliberately lower-recall (it is the precision half of
the §3.2 trade); at s512 the two agree (16/16) because every residual dead row
there is type-level.

## D2 — steer-decision replay log (schema v1.3) + replayer

`temper/steer/log.py`, `temper steer-replay`. Additive over v1.2: nothing in
the M2.x record format changed; a steered cell writes one
`<out>.steer/<problem>.jsonl` per game.

Event kinds: `meta` (game, problem, schema_version `1.3`, K, steps, envelope,
`verdict_config_sha256`, view sha), `spawn`, `rng`, `checkpoint`, `decision`,
`kill`, `clone`, `emit`, `done`. `checkpoint` carries `nfe_at`,
`committed_token_count`, `canvas_prefix_sha256`, `mask_share` vs
`expected_mask_share`, `r0_flags`, `r2_stubs`, and `r1`
{`ok`, `stderr_sha256`, `error_codes`, `informed_codes`, `fragment_exact`}.

**Replay contract.** `replay_game(events, config)` re-derives every decision
from the log alone — no GPU, no model, no rustc. The patience counter is
RECOMPUTED from the checkpoint history (`persistence_of`), never read from a
stored field, and each derived action/reason is compared against the recorded
`decision` event. Policy state the loop knows but a replayer cannot (live
particle count, remaining budget) rides on the checkpoint record as logged
STATE; the conclusion is always recomputed. Tamper tests pin the acceptance:
poisoning an R0 flag, poisoning informed evidence, mutating a decision, and
dropping a decision event each raise `ReplayMismatch`.

## D3 — NFE & budget metering

`ParticleResult` gains `nfe_model`, `nfe_verifier_calls`, `verifier_wall_s`
(additive; `nfe` stays the v1.2 model-forward count, so every existing reader
is unchanged) plus an `nfe_total` property that reads `nfe`. `temper/steer/
metering.py` provides `GameMeters` (per-game, envelope-asserting),
`CellMeters` (aggregate + `nfe_total <= n_problems * envelope` assert), and
`aggregate_nfe` (v1.2-compatible done-line meters).

Verifier work is **never** folded into NFE (design §2.2): `verifier_wall_s` is
a separate axis, and `GameMeters.verifier_fraction_of_budget_wall` is the
quantity kill-criterion 4 watches. Unit-tested against hand-built fake games
(envelope overflow raises; a kill stops accrual; verifier calls do not move
`nfe_model`).

## D5 — held-in guard (`SteerProblemView` allowlist)

`temper/steer/view.py`: `ALLOWED_TASK_FIELDS = ("name", "prompt")` and
`SteerProblemView.from_task(task)` copies exactly those keys; `fn_name` and
`signature_line` are DERIVED from the prompt with the same regex the export
instrument uses. Adversarial tests: a task dict with readable `tests`/
`doctests`/`original` still yields a view whose repr and payload contain none
of them; no reward-side module subscripts a forbidden key; `view.py`'s only
imports are `__future__`, `dataclasses`, and `temper.multipl_e.export` (the
prompt-side regex).

Structural note: the ghost closure renders `prompt + canvas-body + closer` and
never the `tests` string — pinned directly by a test that walks every
non-blank line of the vendored tests and asserts none appears in the checked
program.

## D6 — paired & Bayesian tooling (`scripts/m3_cells.py`)

Primary decision quantities (rev1 R4): per-problem **migration matrix** +
one-sided **sign test**; **exact McNemar** two-sided alongside. Jeffreys
pooled posterior is printed with its iid caveat and never decides a gate.

Reference reproduction (D6 acceptance, `--reproduce`, exit 0):

| anchor | honest p@1 | expected (M2.4b) | NFE/prob | gen wall |
|---|---|---|---|---|
| s96 | 0.16 | 0.16 | 384 | 6.18 h |
| s128 | 0.20 | 0.20 | 512 | 8.82 h |
| s256 | 0.44 | 0.44 | 1024 | 7.21 h |
| s512 | 0.64 | 0.64 | 2048 | 14.48 h |

| Jeffreys reference | reproduced | design text |
|---|---|---|
| x=13 P(θ>0.44) | 0.790 | 0.79 |
| x=14 P(θ>0.44) | 0.886 | 0.886 |
| x=16 P(θ>0.44) | 0.978 | 0.978 |
| x=18 P(θ>0.64) | 0.796 | 0.795 |

Detectable-effect statement emitted with every paired comparison: at n=25
paired draws one-sided α=0.05 needs **≥5 discordant problems all in one
direction** (P = 1/32); fewer flips, or flips split between directions, cannot
clear the sign test.

## D7 — verdict-config freeze (v0) + tamper detection

`steer_verdict_config.json` at repo root, schema `steer-verdict-config/1`,
version **v0**, frozen sha256
`6d3440b9a43ba9dd1f7ac012339c79fbea25b08b0c380031965e78cd43491d9f`.

The digest is canonical JSON (sorted keys, no whitespace) of the payload
WITHOUT its `sha256` field, so formatting churn does not change the identity but
any semantic edit does. `load_verdict_config()` re-derives and compares; a
mismatch raises `VerdictConfigError` naming the tamper. `scripts/
m3_freeze_verdict_config.py --check` is the CI-shaped gate; `--write` re-stamps
after a labeled version bump.

v0 contents (each transcribed from the design text, with provenance strings in
the file): informed classes E0277/E0282/E0283/E0507/E0382 + the same-family
substantive set (E0308/E0499/E0061/E0599/E0369/E0502/E0505); patience
consecutive_checkpoints 2, hole_proximity_lines 1; R0 fatal flags
prose_after_fence / fence_unterminated / mask_share_divergent /
fn_header_missing (extract_rejected_final is recorded but NOT fatal — the game
must still emit); R2 markers `todo!(`, `unimplemented!(`, `panic!(`; checkpoint
grid {0.25,0.5,0.75,1.0}; emission
`best_r1_clean_by_mean_commit_conf_ties_lowest_temp`; clone temp_step 0.2,
cap 0.8, clone_cap_per_parent 2; envelopes {1024, 2048}, k_max_eff 8.

**D4 will repin this file.** The patience parameters are placeholders until
D4's live-canvas table exists (design §7 D4: "the pass rule parameters are SET
by this table and committed, not hand-waved"). The repin is a labeled version
bump with a new sha; both shas will be recorded in `docs/m3.0-report.md`.

## D4 — scaffold status (measurement deferred to the P0→P2 boundary)

The measurement machinery is in place and already runs on committed canvases
(the D1 table above is the same code path on zero-hole canvases). What D4 adds
is the **hole-density sweep on REAL mid-decode canvases**, which requires the
loop to exist in all-off mode — i.e. the P0→P2 boundary. Reported there.

## Driver extensions landed for P0.5/P1

* `--problem-indices 0,4,20,21` — explicit cohort selection (0-based vendored
  order), recorded in the run meta as `problem_indices` and per row as
  `problem_vendored_index`; a conflicting numeric `--problems` is refused.
* `--temperatures 0.4,0.8,1.2` — one canvas per temperature per problem
  (seed = base_seed + j), each row carrying its own temperature; the meta
  records `temperatures` and `K_effective`. This is the (problem, temp, k) grid
  the P1 reachability curve is read from.
* `--hint-file` — ONE extra line appended to the chat prompt; the exact text
  (`hint_text`) and `hint_sha256` are pinned in the run meta, and a hint
  mismatch blocks resume. This is the C-hint knowledge-injection null.
