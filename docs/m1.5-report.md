### Reading

- **The aim — "calibration measurably reduces wrong-API-shape rejections" —
  is NOT met on rates**: extract rejections stayed 3/4 (before, at steps=96)
  and 3/4 (after, at steps=128). What changed is *where* candidates die, and
  without raw text that would have been invisible:
  - **p0 (both runs)**: the calibrated shape is followed *exactly* — module-level
    `ring_new`/`ring_push`/`ring_pop` with the required signatures — but a
    single degenerate artifact (`pub RingBuf { fn new(...) }`: an `impl` block
    missing its `impl` keyword) makes rustc fail with the E-code-less error
    `missing \`enum\` for enum definition`. The rest of p0 (run B) is
    semantically correct overwrite-oldest logic — strip the stray block and
    this candidate plausibly passes. Calibration worked; robustness to one bad
    block is now the bottleneck.
  - **p1 (run B)**: true wrong-API-shape answer — `pub fn new` inside
    `impl RingBuf` plus module-level `pub fn push(&mut self, v: i64)` /
    `pub fn pop(&mut self) -> Option<i64>`: renamed AND self-parameterized
    "free functions" (invalid), text ends mid-expression. Class: API-shape
    mismatch (renamed variant) — the strict same-name impl-method rejection
    string never fired because the names were wrong too; only raw text
    disambiguates this from "echo/wrong problem".
  - **p2, p3 (run B)**: **canvas exhaustion, not API shape** — both commit all
    384 canvas tokens, burn roughly the first third on prose preambles
    (despite "Answer with ONE ```rust fenced code block and nothing else"),
    then get cut mid-`ring_push`; `ring_pop` never exists. p3's surviving code
    has the exact calibrated shape (free fns, right names/signatures).
- Net: the prompt is doing its job where the model actually emits code; the
  remaining killers are (a) degenerate stray blocks, (b) prose budget waste on
  a 384-token canvas, (c) renamed/self methods at high temperature. These are
  cheaper to fix mechanically (repair pass, canvas/anti-prose) than with more
  prompt wording — carried to the M2 spec below.
- Steps note: both after-runs ran the full 128 steps per particle
  (s/step: entropy 1.29–1.31 fresh, 2.30–2.46 sustained/topk — consistent with
  M1's measured overheads; model load 8.5 s; each K=4 run ≈ 18 min wall).

## Extract-rejection case resolved via raw text

**Case: run B p1 — `required symbol(s) 'ring_new', 'ring_push', 'ring_pop'
not defined anywhere in extracted code (prompt echo or wrong problem?)'**
(`bench/ringbuf/runs/20261018T224453Z.raw/p1.txt`, sha256-verified against the
row). Before M1.5 this row was opaque — "prompt echo or wrong problem?" is
wrong on both counts. The raw text shows a **wrong-API-shape failure
(renamed-variant)**: the model half-followed the calibration (struct at module
scope, split out of the impl) but renamed the API to `new`/`push`/`pop`,
wrote `push`/`pop` as module-level functions that still take `&mut self`
(invalid as free fns), and left the canvas mid-expression. The extracted bare
span therefore contains none of the required names. Failure class for
counting: **API-shape mismatch — renamed/self-method variant** (distinct from
M1's same-name `impl`-method class, which the new classifier isolates as
`defined only as inherent impl method(s)`).

Bonus (compile-side, same workflow): run B p0 compiled as `compile_error` with
empty `diag_codes` — replaying its raw text through extract+harness showed the
E-code-less rustc error `missing \`enum\` for enum definition` from the stray
`pub RingBuf { ... }` block (see Reading). The record alone could not have told
us this; `diag_codes` only carries E-codes.

## Anything revealed that belongs in the M2 spec

1. **Persist code-less diagnostics**: rows keep diag *codes* only; E-code-less
   errors (`missing \`enum\` for enum definition`, linker failures) show up as
   `compile_error` with empty `diag_codes`. Store the primary error message
   (or stderr tail) per candidate — one string field, same argument as raw
   text.
2. **Cheap repair pass (L0.5) before giving up on a candidate**: p0-style
   failures are one stray block away from passing. A deterministic cleaner
   (drop unreferenced/degenerate items, e.g. a block whose name is shadowed by
   a required free fn) or a single error-feedback re-ask would likely convert
   p0. Quantified upside available from stored raw text.
3. **Canvas budget vs prose**: multi-item tasks burn canvas on preamble prose
   (p2/p3: ~1/3 of 384 tokens) and die mid-API. Options: canvas 512 for
   multi-item signatures (+~33% wall at measured s/step), or an anti-prose
   instruction/few-shot prefix; raw-text stats now make the waste measurable
   per run.
4. **Automated failure-class taxonomy in eval**: the raw sidecars enable a
   small classifier that tags each rejection row (`impl_method` /
   `renamed_or_self` / `truncated_canvas` / `prose_only` / `echo`); put the
   per-class histogram into `temper eval` so prompt experiments like this one
   read directly off the table instead of requiring manual raw-text reading.
5. **Seed-replay determinism caveat observed**: run A p0 and run B p0 show the
   same observable failure signature (extract ok → compile_error with empty
   diag_codes) at different seeds — the failure mode is prompt/task-driven,
   not seed luck; supports the repair-pass investment over resampling.
