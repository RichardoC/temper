## The minimal fix (chosen option: extract.py extension, NOT a template change)

The task offered "instruction-template tightening in bench.py **or** a
taxonomy/extension in extract.py". Chosen: **extract.py fenced→bare-span
fallback** (`extract_rust` now retries the bare-span path when the fenced
candidate fails the Rust-shape check, with a mask-token exemption so
`incomplete canvas` diagnostics are preserved). Rationale:

1. **Demonstrable on the disease data without regeneration** (phase-0
   constraint): the HumanEval_15 fixtures contain a complete, balanced
   `fn string_sequence`; only the extraction order threw it away.
2. **Zero prompt change** → the M2.3 steps cells stay byte-identical to the
   M2.2 steps=96 cell in every config field except `steps` (template sha
   unchanged), which is exactly what the "was 0.04 a decode-budget artifact?"
   question needs. A template tightening would have changed two variables at
   once and its effect would be unprovable without new generation.
3. Conservative: the bare span keeps its own gates (item header + balanced
   braces); a passing fenced extraction is never revisited; mask-token
   spans keep the sharper `incomplete canvas` rejection.

Template tightening is recorded as an M2.4 option (would need its own A/B
cell, not a silent change).
